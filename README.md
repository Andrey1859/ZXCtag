# ZXCtag

Плагин Paper 1.21.4 (Kotlin): префиксы игроков в списке игроков (таблице) и пакетные NPC со скином Java-аккаунта (с встроенным скином на случай недоступности Mojang).

## Сборка

```sh
./gradlew build
```

Готовый файл: `build/libs/zxctag-1.0.0.jar`. Поместить в папку `plugins`.

## Префиксы игроков

```text
/zxc <ник> <класс> <статус> <лвл> <ус>
/prefix <ник> <класс> <статус> <лвл> <ус>
```

`/zxc` — префикс с буквами ZXC, `/prefix` — без ZXC.

Список игроков (таблица) ограничивает префикс 16 символами (включая коды цвета), поэтому в таблице показывается компактная иконка класса — для `/zxc` с брендом ZXC, для `/prefix` в скобках.

Права: `zxctag.zxc` и `zxctag.prefix` (по умолчанию op). Tab подсказывает ник, класс, статус, уровень и УС. В скобках класса префикса плагин выводит иконку класса — лучник `U+E001`, бард `ⁿ`, жрец `❤`, хранитель `✠`, заклинатель `☠`, некромант `▭`, шут и джокер `Ⴌ`, мушкетер `ὅ`; клиентский мод заменяет их пиксельными иконками. Статус: прем `⒮`, админ `ꚍ`, игрок `U+E002`.

## NPC со скином по нику

Выполнить команду в точке, где должен стоять NPC:

```text
/spawnnpc <имя_NPC> <Java-ник_скина> <класс> <статус> <лвл> <ус>
/rpg spawnnpc <имя_NPC> <Java-ник_скина> <класс> <статус> <лвл> <ус>
```

Например: `/spawnnpc Guard Notch лучник premium 1234.5 10`. Имя NPC и ник скина должны содержать от 1 до 16 латинских букв, цифр или `_`. Используются те же значения, что и в `/zxc`/`/prefix`: классы `бард`, `лучник`, `заклинатель`, `некромант`, `жрец`, `шут`, `джокер`, `мушкетер`, `хранитель`; статусы `none`, `premium`, `admin`. Уровень и УС можно задать любыми значениями — типовые варианты `1`, `5`, `10`, `20`, `30`, `50`, `100` (УС `0`, `1`, `5`, `10`, `20`) подсказываются tab-completion, но принимается любое значение, например `1234.5`.

Скин ищется через API Mojang по Java-нику. Запрос выполняется в фоне, поэтому серверный поток не блокируется. В профиль пакетного игрока добавляется исходное подписанное свойство `textures` Mojang; проверяется, что адрес текстуры ведёт на `textures.minecraft.net`. Если сервер не может достучаться до Mojang, используется встроенный скин NPC (`NpcDefaultSkin`), чтобы NPC назывался и без доступа к API.

Если имя NPC уже занято, команда объясняет почему: занято другим NPC, предыдущее создание ещё выполняется, занято игроком или другой командой табло.

### Как виден NPC

NPC — только отображаемый клиентам пакетный игрок, не подключённый аккаунт. Он создаётся в текущем мире и точке команды; для скина по нику нужен доступ к API Mojang, но при его отсутствии используется встроенный скин.

- В списке игроков (таблице) — компактный тег: бренд ZXC и иконка класса перед именем, бейдж статуса после имени.
- Над головой NPC — полный тег: бренд ZXC, иконки класса и статуса, уровень и УС.
- Поза и углы берутся из снимка клиента (если клиентский мод их отправил перед командой) или с сервера.

Снимок места, стандартной позы, углов корпуса/головы, класса, статуса, уровня, УС и данных скина сохраняется в `plugins/ZXCtag/npcs.yml`; NPC восстанавливаются после перезапуска вместе с префиксом. NPC неподвижен и сам не обрабатывает взаимодействия. Внутренний адаптер рассчитан на Paper 1.21.4.

### Предмет в руке NPC

Подойдите к NPC на расстояние до 5 блоков и используйте:

```text
/npcitem [main|off] [имя_NPC]
/rpg npcitem [main|off] [имя_NPC]
```

Без аргументов предмет из основной руки копируется ближайшему NPC в основную руку. `/npcitem off` копирует предмет из второй руки игрока во вторую руку NPC. Имя NPC необязательно; его можно указать, например `/npcitem Guard off`, но проверка близости всё равно действует. Предмет копируется для отображения и остаётся у игрока. Право: `zxctag.npcitem` (по умолчанию op); экипировка сохраняется в `npcs.yml`.
